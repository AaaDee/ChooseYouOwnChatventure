# Project documentation

This document describes the main technical features and design choices used in the project.

## Core premise

The app is an experimental, yet fully playable game inspired by the classic "Choose Your Own Fantasy" -style gamebooks, especially by the Fighting Fantasy series. The content of the game is generated by prompts passed to a large language model, which creates an ongoing story based on the user prompts. The game in its current form is open-ended, i.e., there is no way to win or lose it as such.

The key technical features of the app are:

- Functioning game logic and core loop
- Use of clean, readable code and good development practices
- Comprehensive testing
- Automated deployment
    - With testing, the core principle is that a PR passing the code check should be ready to go to production without any manual adjustments or follow-up checks to make sure that nothing’s broken
- Up to date dependencies and frameworks
    - As the project has been in on/off development while, several version updates and some framework changes have already taken place (e.g. migration from create-react-app to vite, and from jest to vitest)

## Frontend

The frontend is a React app, using Redux-toolkit for state management, Styled components for styling, and Vitest for testing. Typescript is used, and typing is heavily enforced.

The key premise of the frontend is that while retaining a retro aesthetic, the page should be straightforward to use and navigate, and interactions with the backend (such as loading more content) should be handled smoothly.

As of writing this, the test line coverage is around 73%, with components and custom hooks being tested. Most of the boilerplate code around the Redux state management has been left out of testing.

## Backend

The backend is a Node Express app, which serves the endpoints through a REST API. Typing with Typescript is used here as well.

A substantial part of the backend is the prompting and templating of the OpenAI responses. All OpenAI-related code is contained in a separate folder, so changing the LLM used should be feasible with only minor changes.

The line coverage of the backend is 100%, which was reached because of personal interest in the exercise, rather than any practical or pragmatic considerations.

There is a minimal login and user management component, with the user accounts being stored in MongoDB. Due to the backend having access to the (paid) OpenAI key, user creation is currently disabled.

## Infrastructure

There is an automated CI/CD pipeline with the following key components:

- The front end and backend are built into separate Docker images, which are orchestrated using Docker Compose
- There is a GitHub actions pipeline, which does the following steps:
    - Building the images and running unit tests
    - Running simple integration tests using Playwright
    - Publishing the images on DockerHub
- The project is hosted on a rented Linux server, which pulls the updated images automatically from DockerHub using Watchtower
- The services are routed through an Nginx-based reverse proxy
- The certificates for the domain are managed using LetsEncrypt

## Use of AI

The project uses the OpenAI API for creating the story content. GPT 4 is used for text, and DALL-E 3 for images.

Large language models (mainly ChatGPT and Google Gemini) were consulted for some technical questions during the development process. Other than this, no AI-generated code or other material has been used.
